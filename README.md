# Slack Analyze — Chrome extension

The Chrome MV3 extension that captures Slack history for Slack Analyze.

Capture Slack channel and DM history from the Slack web app, store it in PostgreSQL, and browse, search and analyze it in a Slack-style web UI.

```
┌──────────────────────┐   batches (HTTP, real time)   ┌──────────────┐     ┌──────────────┐
│ Chrome extension     │ ─────────────────────────────▶│ Backend API  │────▶│ PostgreSQL   │
│ (app.slack.com tab)  │   X-API-Key                   │ Fastify :4000│◀────│ :5432        │
│ auto-scroll + live   │                               └──────┬───────┘     └──────────────┘
└──────────────────────┘                                      │ REST + SSE (/api/stream)
                                                              ▼
                                                      ┌──────────────┐
                                                      │ Next.js UI   │
                                                      │ :3000        │
                                                      └──────────────┘
```

| Repo | What it is |
|---|---|
| [slack-analyze-extension](https://github.com/core7matrix/slack-analyze-extension) | Chrome MV3 extension: scrapes the open Slack tab, auto-scrolls up through history, sends batches to the backend, timed auto-sync, live capture, offline retry queue |
| [slack-analyze-backend](https://github.com/core7matrix/slack-analyze-backend) | Node 22 + TypeScript + Fastify. Ingest API (extension → DB), read/search/analytics API, Server-Sent Events for live updates. Applies DB migrations on startup |
| [slack-analyze-frontend](https://github.com/core7matrix/slack-analyze-frontend) | Next.js 15 (App Router) + Tailwind: Slack-like message browser, search, analytics, sync status, admin dashboard |

Clone them side by side (`slack-analyze-backend`, `slack-analyze-frontend`, `slack-analyze-extension` in one folder); the frontend's icon export writes into the extension checkout next to it.


## Install

Needs a running [slack-analyze-backend](https://github.com/core7matrix/slack-analyze-backend).

1. Open `chrome://extensions`, turn on **Developer mode**, click **Load unpacked**, choose this repo's folder.
2. Click the extension icon → **Settings**: Backend URL (e.g. `http://localhost:4000`), API key = the backend's `INGEST_API_KEY`. Click **Test connection**.
3. Open https://app.slack.com and sign in.

After changing the code, click **Reload** on the extension in `chrome://extensions` and reload the Slack tab. The icons in [icons/](icons/) are generated by `brand/export.mjs` in [slack-analyze-frontend](https://github.com/core7matrix/slack-analyze-frontend).

## Several browsers / several Slack users

Install the extension in every browser that is signed in to Slack — Chrome, Edge, Brave, Opera, or separate Chrome profiles (each profile is its own install). In each one:

1. Load this folder as above (Edge: `edge://extensions`, Brave: `brave://extensions`).
2. **Settings**: same Backend URL and API key, plus a **browser label** such as `Edge — Jane's laptop`. Save, then **Test connection**.

Each install gets its own id and reports the Slack user it's signed in as (read from Slack's `localConfig_v2` in the page). Messages are still stored once; the backend also records which account captured which conversation, so:

- **Sync** page → **Accounts & browsers** shows every account, its browsers, online status (heartbeat every minute while a Slack tab is open), conversations visible and messages captured.
- The **View as** tabs above the main content (Messages, Search, Analytics, Sync) limit everything to the conversations one account can see; switching reloads the page for that account and, if the open conversation isn't in that account's Slack, opens its most recent one. DMs are shown under that account's name for them; with **All accounts** a DM reads "Alice, Bob".
- If the user can't be detected, the install itself stands in as the account (`collector:<id>`), labelled with the browser label.

## Capture history

- **Range** (Sync tab): "from now back to *N* days ago / *N* months ago / all history".
- **Sync open channel**: scrolls the current channel upward until the range cutoff or the start of the channel, sending messages as it goes.
- **Channels tab → Refresh from Slack sidebar**: reads every conversation in the sidebar (channels, private channels, DMs, group DMs). Tick the ones you want, then **Sync selected** — the extension visits each one in turn.
- **Auto-sync**: re-syncs the selected conversations every 15 min – 24 h. With **Incremental** on, auto runs stop at messages already captured, so they are quick.
- **Live capture**: while Slack is open, new messages in **every** channel, DM, group DM and thread the signed-in user belongs to are sent within ~1 s — not just the one on screen. The extension listens to the real-time feed Slack's own page already receives (its WebSocket, hooked by [rtm-hook.js](rtm-hook.js)); it sends nothing to Slack and uses no tokens. Edits and reaction changes are picked up too, and the open channel is additionally read from the page. The popup's Settings tab shows whether the real-time feed was detected (reload the Slack tab after installing or updating the extension).
- If the backend is down, batches are queued in the extension (up to 2,000) and retried every minute.

Keep the Slack tab open (it can be in the background) while a sync runs. Collapsed sidebar sections are not read; expand them before refreshing the channel list.

## How capture works (and its limits)

The extension reads Slack's **rendered page** — it does not use Slack's API or tokens. That means:

- It only sees what your account can see in the browser, at the speed Slack loads history. Large channels take minutes.
- **Slow loading**: after every scroll step the extension waits until Slack has finished rendering (no DOM changes, no spinner), not just a fixed delay. At the top of the loaded history it keeps nudging Slack for older messages for up to **Load patience** seconds (Settings, default 60) before deciding there is no more. Scroll jumps that skip rows are detected and re-read, and a **verification pass** scrolls back down once to collect rows that rendered late. If a run stops without reaching the channel start or the date range, the popup log shows a warning — re-sync or raise Load patience.
- Chrome slows timers in background tabs, so syncs run fastest with the Slack tab visible (its own window is fine). The tab is protected from being discarded while a sync runs.
- Slack doesn't document its DOM. All selectors live in the `SEL` table at the top of [content.js](content.js); if Slack changes its markup, fix them there.
- Consecutive messages from the same person hide the sender in Slack's UI; the extension copies the sender forward from the group's first message.
- **Threads**: with **Capture thread replies** on (default), the extension opens every thread that has replies in Slack's side panel, clicks "show more replies", scrolls through it and stores the replies (shown in the web UI's thread panel). Threads whose reply count hasn't changed since the last complete capture are skipped.
- **Full message bodies**: collapsed "Show more" messages and attachments are expanded before reading. Rows captured while still loading (placeholders, empty bodies) are re-read until complete; any left are reported in the popup log.
- Free Slack workspaces hide history older than 90 days; the extension stops when no more history loads.

Only capture workspaces you're authorized to export, and follow your organization's Slack data policies.

## Files and images

With **Settings → Files & images** on (default), the extension downloads files attached to captured messages using the browser's Slack sign-in and uploads them to the backend, which stores each file once. See *Files and images* in the [backend README](https://github.com/core7matrix/slack-analyze-backend#files-and-images) for the lease queue, retries and storage options.
